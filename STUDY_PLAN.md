## 3. Пройденные темы — не повторять без причины

### C# и .NET

- `var`, `object`, `dynamic`, статическая типизация, boxing/unboxing.
- `ref`, `out`, `in` как модификаторы параметров.
- `class`, `struct`, `record`, `with`, value types и reference types.
- LINQ: deferred execution, `IEnumerable<T>` и `IQueryable<T>`.
- Async/TAP: `async`/`await`, асинхронный I/O, `Task.Run`, `Task.WhenAll`, ошибки асинхронных операций.
- `CancellationToken`: передача вниз по цепочке вызовов для отмены ненужной работы.
- Generics: назначение, типобезопасность, сравнение с `object`, boxing/unboxing, ограничения `where`, ограничение интерфейсом и `where T : class`.
- Variance: ковариантность `out T` и контравариантность `in T` на generic-интерфейсах.

### Алгоритмы

- Массивы, `Dictionary`, подсчёт частот, поиск первого уникального элемента, оценка O(n).
- Поиск первого повторяющегося элемента через `HashSet<int>`; результат `int?`, `null` для null/пустого массива или отсутствия дубликатов.
- Длина самого длинного непрерывного подмассива без повторов: sliding window + `Dictionary<int, int>` с последними индексами. Средняя сложность O(n) по времени и O(n) по дополнительной памяти.

### Практика проектирования

- Разбирали модель истории финансовых операций: `Operation` представляет бизнес-действие, а `Transaction` — отдельное изменение конкретного счёта.
- Разбирали связь нескольких записей `Transaction` с одной `Operation`, в частности для перевода между счетами.
- Разбирали необходимость хранить тип бизнес-операции в `Operation`, а не дублировать его в каждой записи `Transaction`.
- Начали реализацию истории операций в `personal-finance-api`; интеграцию и тестирование ещё нужно завершить.

## 6. Учебный проект: personal-finance-api

Стек: .NET 10, ASP.NET Core, PostgreSQL, EF Core, MediatR, Swagger; тесты MSTest. Проект используется для практики и обучения, изменения сначала обсуждаем.

### Зафиксированные решения и реализованные изменения

- `Account.Version` используется как concurrency token; `AccountVersionInterceptor` увеличивает версию изменяемого `Account`.
- Есть тесты на увеличение `Version` и конфликт устаревшего обновления через два контекста.
- Исключения API используют `IApiException` с `Status`, `Title`, `Detail`; глобальный обработчик формирует `ProblemDetails`.
- Для перевода между счетами используется один `SaveChangesAsync()`. Для обычного реляционного EF Core сохранение этих изменений атомарно, поэтому отдельная явная транзакция только ради этих изменений не добавлялась.
- Переводы между разными валютами запрещены до реализации конвертации.
- Добавлена валидация DTO через Data Annotations.
- Публичный `AccountItemDto` больше не раскрывает доменную модель `Currency`; используется отдельный DTO.
- По состоянию на 20.10.2026 тесты после этих изменений проходили.

### История финансовых операций — текущая задача

#### Принятая модель

- `Operation` представляет бизнес-действие: например, пополнение, снятие или перевод.
- `Transaction` представляет изменение одного конкретного счёта.
- Одна операция может быть связана с одной или несколькими транзакциями.
- Для перевода между счетами создаются две связанные записи `Transaction` с противоположными знаками, относящиеся к одной `Operation`.
- Тип бизнес-операции хранится в `Operation`. Это позволяет отличать перевод от других видов действий, не дублируя тип в каждой записи `Transaction`.

- Созданы и применены миграции для таблиц `Operations` и `Transactions`.
- Реализован `OperationHistoryService` для формирования записей истории:

  - снятие — одна отрицательная запись;
